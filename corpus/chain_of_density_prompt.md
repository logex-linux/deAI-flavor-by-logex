# Chain-of-Density：用"硬长度约束 + 强制新信息"破车轱辘话

来源：Adams, Fabbri, Lockard, et al. (Salesforce Research / Columbia / Yale)
《From Sparse to Dense: GPT-4 Summarization with Chain of Density and Inconspicuous Title》
**EMNLP 2023**  |  arXiv:2309.04269v1  |  开源了 5000 条 CoD 摘要
本地全文: /tmp/cod.txt

## ★★★ 最重要的经验结论（报告3的基石）
**"humans prefer summaries that are almost as dense as human-written summaries and
more dense than those generated by a vanilla GPT-4 prompt."**
（人类偏好的密度**高于 GPT-4 默认输出的密度**）
→ **量化表述"AI默认讲车轱辘话"：模型默认输出的信息密度低于人类偏好。**
→ 4 位标注者中，**2 位偏好倒数第二版**（更短的那一版），另 2 位偏好最终版。
  → 即：**在某些人眼里，连 CoD 的最终版都还不够密。**

## ★★★ 完整 CoD Prompt 原文（可直接改造为中文"反车轱辘话"模板）

```
Article: {{ARTICLE}}

You will generate increasingly concise, entity-dense summaries of the above Article.

Repeat the following 2 steps 5 times.

Step 1. Identify 1-3 informative Entities (";" delimited) from the Article which are
        missing from the previously generated summary.

Step 2. Write a new, denser summary of identical length which covers every entity and
        detail from the previous summary plus the Missing Entities.

A Missing Entity is:
- Relevant:   to the main story.
- Specific:   descriptive yet concise (5 words or fewer).
- Novel:      not in the previous summary.      ← ★ 强制新信息
- Faithful:   present in the Article.
- Anywhere:   located anywhere in the Article.

Guidelines:
- The first summary should be long (4-5 sentences, ~80 words) yet highly non-specific,
  containing little information beyond the entities marked as missing. Use overly verbose
  language and fillers (e.g., "this article discusses") to reach ~80 words.
- Make every word count: re-write the previous summary to improve flow and make space
  for additional entities.
- Make space with fusion, compression, and removal of uninformative phrases
  like "the article discusses".                              ← ★ 明确点名要删的填充语
- The summaries should become highly dense and concise yet self-contained, e.g., easily
  understood without the Article.
- Missing entities can appear anywhere in the new summary.
- Never drop entities from the previous summary. If space cannot be made, add fewer
  new entities.

Remember, use the exact same number of words for each summary.   ← ★ 硬长度约束

Answer in JSON. The JSON should be a list (length 5) of dictionaries whose keys are
"Missing_Entities" and "Denser_Summary".
```

## 机制拆解（为什么这套 prompt 能压掉车轱辘话）★
1. **硬长度约束**（"use the exact same number of words for each summary"）
   → 长度不变，只能靠**压缩**来腾空间。这是唯一能在不依赖模型自觉的前提下
     强制"删废话"的手段。**模型无法用"多写一点"来绕过。**
2. **强制 Novel 约束**（"not in the previous summary"）
   → 每一轮必须引入前文没有的新实体。**这直接把"重复"变成不可行**，
     而不是靠"请不要重复"这种模型可以敷衍的软指令。
3. **明确的敌人**（点名的 uninformative phrases "the article discusses"）
   → 把抽象的"不要啰嗦"变成**具体的可搜索字符串**。
4. **Never drop**（不许丢旧实体）
   → 防止模型用"缩短"冒充"压缩"，保证是融合而非丢弃。
5. **量化指标做代理**（entities per token）
   → 论文用"平均每 token 的实体数"作为密度的可操作代理。**可测量才有优化方向。**

## 对中文"反车轱辘话"prompt 的直接改造（本报告设计，非论文原文）
把 CoD 的三要素迁移：
- 硬长度约束 → "全文不超过 N 字；改写后字数不得增加"
- Novel 约束 → "每一段必须包含至少一个前文没有出现过的具体信息：一个专有名词、
  一个数字、一个地名、一个时间、一个反例、或一个限定条件"
- 明确的敌人 → 点名禁用的具体填充串（见报告2的黑名单）
- 可测量代理 → 相邻句实词重复率（CCL 2023：人类 0.481，GPT 0.831）
