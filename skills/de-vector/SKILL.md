# de-vector：破坏可期望的向量

**核心命题**：AI 味的载体不是某个词，是**方差被压缩**。

Liang et al.（ICML 2024）的原文是：

> "…corpora with generated text appear to **compress the linguistic variation and epistemic
> diversity** that would be expected in unpolluted corpora."

**因此本 skill 的操作对象不是词，是方差。**

> **关于这句引语**：已逐字核对 arXiv HTML 全文，一致。完整出处、作者列表、以及同一篇里
> 另一句容易被混引的相邻句子，见同目录 `REFERENCES.md` 第一节。

## 一、开始前必读的三条元规则

### 元规则 1：不要做同义词替换

把"重要"换成"关键"，把"显著"换成"明显"——**在两个检测轴上都是完全无效的**：

| 轴 | 同义词替换 |
|---|---|
| 困惑度轴（Binoculars 类[^1]） | 两个词概率都高，logp 不变 → **无效** |
| 风格轴（CCL 2023 类） | 不引入新概念，TTR 与实词丰富度不变 → **无效** |

它是"降 AI 味"最普遍的浪费。**本 skill 禁止用它。**

### 元规则 2：不要"把长句改短"

这是本 skill 与大多数降 AI 味教程的**根本分歧**。

把长句拆短只削减均值附近的值，**句长方差（SD）反而停滞甚至下降**。实测推导：

| 操作（n=10 句，初始 SD=4.32，人类基线 9.248） | 结果 SD | 达标？ |
|---|---|---|
| 把 8 句改成短句 | 7.39 | ✗ |
| **把 2 句做长短交错** | **10.39** | **✓** |

**SD 对方差敏感、对均值不敏感。** 要抬 SD，必须**同时制造两端**。

### 元规则 3：不得新增事实

注入的具体指称必须来自原文或用户提供。**编造地名、数字、人名、引语是错误，不是润色。**
若某处需要一个具体指称而材料中没有，就收窄说法，不要补造。

> 这与 humanizer 的原则一致："Do not invent facts... You may not add a factual claim."

## 二、五步流程

### 第 1 步：数句子，定交错预算

```
句数 N <= 15  → 需要 2 对交错
句数 N <= 35  → 需要 4 对交错
句数 N >  35  → 需要 6 对交错
```

**一对交错 = 一个极短句（6–10 词）与一个极长句（38–52 词）落在相邻位置，词数极差 >= 18。**

交错对必须**相邻或近邻**。因为 SD 是全局统计量，两端的值离均值越远贡献越大（平方项）；
分散在文章两端的效果远不如放在一起。

### 第 2 步：逐段注入一个不可替代的具体指称

**每段至少一个**，且必须满足"不可替代"——删掉它，段落会丢失可核对的信息。

| 指称类型 | 例子 |
|---|---|
| 专有名词（地名/机构/产品/书名） | 南三环木犀园、天雅、MDPI 的 Sensors |
| 精确数字、日期、时长 | 七十四天、十一天、2026 年 8 月 |
| 具体动作（动词，非抽象名词） | 存原始快照、记下取数时间 |
| 第一人称经验、身体状态 | 那种等待很磨人 |
| 自我更正 | 我本来以为…其实… |
| 真正的括号插入 | （这周已经第二次了） |

**CCL 2023 的支撑**：人类 字型例比 0.648 vs ChatGPT 0.470；仅出现一次的词占比 0.588 vs 0.365。
具体指称同时抬 TTR 与可核对性，是唯一在两个轴上都不负面的操作。

### 第 3 步：压低相邻句实词重复率

**人类 0.481 / ChatGPT 0.831。** 这是"车轱轳话"的直接量化。

做法：让相邻句不再重复同一批实词。

- 换主语（不要每句都用同一个主语开头）
- 换论元（同一事件从不同参与者的角度说）
- 换段落论证任务（每段承担新的论证任务，不重复上一段已完成的观点）

**不要**用同义词轮转替代主语（"主角→主人公→核心人物→主角"）——那是 humanizer §11 点名的
"synonym cycling"，是 AI 痕迹而非解药。

### 第 4 步：删除结构性标记

每处删除都直接改变对应指标：

| 删除对象 | 目标指标 | 人类 → AI |
|---|---|---|
| "和/与"等连词 | 连词密度 | 0.013 → 0.036（每 43 词删 1 个） |
| "包括A、B、C、D等"同义场并列 | 句均并列短语数 | 0.251 → 0.729 |
| "不是…而是""不仅…而且""综上所述"等模板 | 模板密度 | 0–2/千字 → >25/千字 |
| 破折号 —— | 破折号密度 | 低 → 高 |
| **四字格与成语** | 四音节及以上词占比 | 0.027 → 0.047 |
| "在…中发挥着""对…具有"等静态介词堆叠 | 介词密度 | 0.029 → 0.043 |
| 抽象名词化外壳（"进行/实现/推动/构建/体现+抽象名词"） | 句均词性数量 | 5.507 → 3.151 |

**★ 注意四字格**：它在训练语料里高度固化，是**低意外** token。
当作"文采"注入是在往 AI 的方向走。成语只在该成语本身是论点的必要术语时保留。

### 第 5 步：朗读验收（不可跳过）

**这一步无法被任何统计量替代。**

读给自己听，标记所有"舌头打结"的句子。然后做三个检查：

1. **搜索检查**：全文搜"不是""而是""首先""其次""总之"，再看破折号密度。
   **不是要求一个没有，而是看是否泛滥。**
2. **节奏检查**：段落长短是不是清一色，观点是不是永远四平八稳。
   **"匀速，就是机器转速。"**
3. **冷处理**：放半天再读，或发给一个不知道你用了 AI 的人。

## 三、可量化的验收

脚本 `ainoise_meter.py` 已随本 skill 附带（同目录，无需另装位置）：

```bash
pip install jieba
python3 ainoise_meter.py 你的文章.txt
python3 ainoise_meter.py 你的文章.txt --json      # 机器可读
echo "文本" | python3 ainoise_meter.py -            # 也可走 stdin
```

**判读优先级**（从高到低）：

| 信号 | 人类基线 | 你该打到 |
|---|---|---|
| **交错锚点对数** | 2–6 对 | 按句数达标（见第 1 步） |
| 句式模板密度 | 0–2 处/千字 | < 3 处/千字 |
| AI 高频抽象词密度 | < 3 个/千字 | < 5 个/千字 |
| 句长方差 SD（词） | 9.248 | > 7.5 |
| 相邻句实词重复性 | 0.481 | < 0.60 |
| 连词密度 | 0.013 | < 0.020 |
| 综合指数 | < 30 | < 40 |

**注意**：CCL 2023 的基准来自**开放域问答**语料。公文、诗歌、新闻通稿、学术论文的统计结构不同，
工具会误报。公文与文献综述本身就会被判高分——那是语体，不是 AI 痕迹。

脚本的已知局限（动词/形容词/副词/代词密度为占位 0、词表是操作化近似）见
`REFERENCES.md` 第五节。

[^1]: Binoculars 指 Hans et al., *Spotting LLMs With Binoculars*, ICML 2024（[arXiv:2401.12070](https://arxiv.org/abs/2401.12070)）。
      它是与 Liang et al. 那篇**不同**的论文，分别对应困惑度轴与风格轴，不要混引。

## 四、什么不要做

| 不要做 | 为什么 |
|---|---|
| 同义词替换 | 两个轴上完全无效 |
| 把长句一律改短 | SD 对方差不敏感，会停滞 |
| 塞入四字格/成语"增文采" | 是低意外 token，反向操作 |
| 加破折号"显思维跳转" | 破折号是 AI 高频标记 |
| 硬凑口语词、方言、语气词 | 会产生"伪俗语"——每个零件眼熟，组合无出处 |
| 在通篇整齐的分析句里定点投放一个口头禅 | 这叫"装松弛"："像穿西装的人突然翘了个二郎腿" |
| 把"不是…而是"禁用到对话与直接引语里 | 人物冲突时说"我不是怪你，我是觉得你至少该告诉我一声"很自然 |
| 为了让分数好看而编造具体指称 | 违反元规则 3，是错误不是润色 |
| 把随机生僻词堆进去冲高困惑度 | 分数会达标（随机串均分 1.35 > 人类 1.0），文本已死 |

## 五、与报告的关系

本 skill 是**报告四**（`reports/report4_injection_deai.md`）的操作化实现：

| 报告四章节 | 本 skill 对应 |
|---|---|
| §3.2 交错 vs 改短的算术 | 元规则 2 + 第 1 步 |
| §4 该注入什么 | 第 2 步 + 元规则 1 |
| §3.1 指标分级表 | 第 3、4 步 |
| §5.1 剂量处方 | 第 1、2、4 步的频次 |
| §7 诚实的边界 | 第 5 步 + 第三节的语体警告 |
| §8 工具行为 | 第三节的判读表 |

**本 skill 与报告三（prompt 约束）的关系**：
报告三在**生成阶段**用硬约束把文本挡在 AI 分布之外；本 skill 在**生成后**对漏网部分做外科手术。
两者不冲突，也不重复——最优组合是先生成时用报告三的约束，再用本 skill 检查修补。
